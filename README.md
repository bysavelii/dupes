# dupes

`dupes` — программа для командной строки, которая помогает освободить место на диске. Она находит в папке одинаковые файлы и похожие фото, показывает, сколько места можно освободить, и по вашей команде убирает лишнее **в корзину**. Навсегда ничего не удаляется: всё, что убрала программа, можно вернуть из корзины.

Пока вы не добавили `--yes`, программа ничего не меняет на диске: она только показывает результат.

Файлы, которые уже лежат в корзине, не проверяются — какие папки считаются корзиной, описано в разделе [«Какие папки считаются корзиной»](#какие-папки-считаются-корзиной).

## Установка

1. Установите Rust: откройте [rustup.rs](https://rustup.rs) и выполните команду, которую там покажут.
2. В папке с программой выполните:

   ```
   cargo install --path .
   ```

После этого команда `dupes` доступна в терминале. Проверить установку можно так:

```
dupes --version
```

Программа ответит `dupes 0.1.0`. Сокращённая запись — `dupes -V`.

## Как пользоваться

### Поиск одинаковых файлов

```
dupes ~/Загрузки
```

Программа просмотрит папку вместе со вложенными папками и покажет группы файлов с одинаковым содержимым. Жёсткие ссылки и один и тот же файл, видимый по двум путям, считаются одним файлом, а не копиями. В каждой группе первым стоит файл с пометкой «(самый старый)» — он останется, остальные считаются лишними копиями. В конце программа напишет, сколько места освободится, если убрать все лишние копии. Файлы при этом не трогаются.

### Поиск похожих фото

```
dupes --similar ~/Фото
```

Так программа найдёт не только одинаковые файлы, но и одно и то же изображение в другом размере или качестве (форматы JPEG, PNG и WebP). Первым в группе стоит фото с пометкой «(лучшее качество)» — его программа оставит.

Насколько фото должны совпадать, задаёт параметр `--similarity` — число от 50 до 100 (по умолчанию 90). Чем число больше, тем строже отбор:

```
dupes --similar --similarity 95 ~/Фото
```

`--similarity` работает только вместе с `--similar`.

### Пробный запуск: что уйдёт в корзину

```
dupes --trash ~/Загрузки
```

С параметром `--trash` программа показывает, что в каждой группе останется («остаётся: …») и что уйдёт в корзину («в корзину: …»). Это пробный запуск: файлы остаются на месте, корзина не затрагивается. Работает и с похожими фото: `dupes --similar --trash ~/Фото`.

### Перенос в корзину

```
dupes --trash --yes ~/Загрузки
```

Параметр `--yes` подтверждает перенос: лишние копии отправляются в корзину системы. Параметр `--yes` работает только вместе с `--trash`.

Перед переносом программа ещё раз проверяет каждый файл. Если файл после поиска изменился или пропал, его не трогают, а в отчёте написана причина. Если изменился файл, который должен остаться, вся группа остаётся нетронутой. Если лишний файл оказался тем же самым файлом, что и оставляемый, он не переносится. Сбой с одним файлом не мешает остальным.

Место на диске освободится, только когда вы очистите корзину; до тех пор файлы можно вернуть из неё.

Если файл лежит на другом диске, чем ваша домашняя папка, он попадает в корзину того диска (папка `.Trash-<номер пользователя>` в корне диска).

### Что остаётся в группе и почему

- Среди одинаковых файлов остаётся **самый старый** — с самым ранним временем изменения. Скорее всего, это оригинал, а остальные — копии, сделанные позже. Если время одинаковое, остаётся файл с более коротким путём, а при равной длине — тот, чей путь идёт первым по алфавиту.
- Среди похожих фото остаётся фото **в лучшем качестве**: с самым большим разрешением, затем с самым большим размером файла. Так вместо оригинала не останется уменьшенная копия.

### Какие папки считаются корзиной

Программа не заходит в папки корзины: файлы там уже выброшены, и если бы оставляемой копией стала та, что лежит в корзине, после очистки корзины пропали бы все копии. Корзиной считается папка, у которой:

| Имя папки | Чья это корзина |
|---|---|
| `Trash`, внутри которой есть папка `files` или `info` | корзина в домашней папке пользователя в Linux (обычно `~/.local/share/Trash`) |
| `.Trash-<номер>`, например `.Trash-1000` | корзина пользователя на другом диске в Linux |
| `.Trash` | общая корзина диска в Linux; в macOS — корзина в домашней папке (`~/.Trash`) |
| `.Trashes` | корзина диска в macOS |
| `$RECYCLE.BIN` (большие или маленькие буквы — неважно) | корзина диска в Windows |

Кроме `$RECYCLE.BIN`, имена сравниваются с учётом больших и маленьких букв: обычная папка `trash` или `TRASH` корзиной не считается и проверяется как любая другая. Корзина узнаётся по имени и устройству папки, а не по тому, чья это домашняя папка, — поэтому не проверяются и корзины других пользователей, если они попали в проверяемую папку.

Если указать саму корзину или папку внутри неё, программа ничего не проверит и ответит, что одинаковых файлов (или похожих фото) не найдено.

### Отчёт для скриптов: `--json`

```
dupes --json ~/Загрузки
dupes --json --trash --yes ~/Загрузки
```

С параметром `--json` программа выводит отчёт в формате JSON — для скриптов и других программ. Сообщения о файлах, которые не удалось прочитать, попадают только в поле `skipped`. Поля есть всегда; если поле к этому запуску не относится, в нём `null`.

| Поле | Значение |
| --- | --- |
| `mode` | `"duplicates"` — одинаковые файлы, `"similar_photos"` — похожие фото |
| `similarity_percent` | порог похожести; `null` при поиске одинаковых файлов |
| `action` | `"report"` — только отчёт, `"dry_run"` — пробный запуск (`--trash`), `"trash"` — перенос (`--trash --yes`) |
| `groups` | список групп |
| `reclaimable_bytes` | сколько байт освободится, если убрать все лишние копии |
| `trashed_count` | сколько файлов перенесено в корзину; `null`, если перенос не запускали |
| `trashed_bytes` | сколько байт перенесено в корзину; `null`, если перенос не запускали |
| `failed_count` | сколько файлов не удалось перенести; `null`, если перенос не запускали |
| `skipped` | файлы и папки, которые не удалось прочитать |

Каждая группа в `groups` — это `{"keep": …, "extras": […]}`: `keep` — файл, который остаётся, `extras` — лишние копии.

- У файла в `keep` и в `extras` есть поля `path` (путь), `size` (размер в байтах), `width` и `height` (размеры фото в пикселях; `null` для одинаковых файлов).
- У лишней копии в `extras` есть ещё `status` и `error`. Значение `status`: `null` — переноса не было, `"trashed"` — перенесена в корзину, `"failed"` — перенести не удалось. При `"failed"` в `error` лежит `{"code": …, "message": …}`: `code` — короткое имя причины (`kept_file_changed`, `same_file_as_kept`, `changed_since_scan`, `vanished`, `access_denied`, `unexpected`), `message` — объяснение по-русски; иначе `error` равно `null`.
- Каждая запись в `skipped` — это `{"path": …, "reason": …, "message": …}`: `reason` — короткое имя причины (`access_denied`, `vanished`, `damaged_image`, `unsupported_image`, `image_too_large`, `unreadable`), `message` — объяснение по-русски.

Пример для одной пары одинаковых файлов:

```json
{
  "mode": "duplicates",
  "similarity_percent": null,
  "action": "dry_run",
  "groups": [
    {
      "keep": {"path": "/home/anna/Загрузки/отчёт.pdf", "size": 1048576, "width": null, "height": null},
      "extras": [
        {"path": "/home/anna/Загрузки/отчёт (1).pdf", "size": 1048576, "width": null, "height": null, "status": null, "error": null}
      ]
    }
  ],
  "reclaimable_bytes": 1048576,
  "trashed_count": null,
  "trashed_bytes": null,
  "failed_count": null,
  "skipped": []
}
```

(В настоящем выводе JSON разбит на строки с отступами.)

## Коды возврата

| Код | Что значит |
| --- | --- |
| 0 | всё прошло успешно |
| 1 | с указанной папкой что-то не так: её нет, это файл или нет доступа |
| 2 | ошибка в параметрах команды: подсказка выведена на экран |
| 3 | с параметром `--yes` не удалось перенести в корзину хотя бы один файл: он остался на месте, причина указана в отчёте |
